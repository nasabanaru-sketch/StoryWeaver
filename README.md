# StoryWeaver Live 🎭✨

> **完全ローカル稼働型・没入型キャラクター転生 AI インスタレーション**  
> 展示会場やイベント現場で、来場者の「顔写真（Webカメラ）」と「生の発話音声（マイク）」から、リアルタイムにアニメ調キャラクターイラストとセリフ・アートカードを生成します。

---

## 🌟 開発コンセプトと作者の想い (Concept & Vision)

> **「音声の感情を使って生成AIを動かすことで、もっと心揺さぶる没入型体験が世の中に増えたら面白い」**

従来の画像生成AIや対話AIの多くは、「キーボードでテキストプロンプトを打ち込む」という静的な体験が中心でした。  
しかし、人が感情を込めて声を張ったり、切なく囁いたり、照れながらセリフを発するときの「生々しい息遣いや演技ニュアンス」には、文字情報（テキスト）だけでは決して伝わらない膨大な情動が宿っています。

もし、**自分が発した声のトーンや叫び、息の抜き方によって、召喚されるキャラクターの表情やオーラがリアルタイムに劇的に変化したなら？**  
体験者が作品世界の主人公になりきって本気でセリフを叫び、その瞬間の感情がそのままビジュアルとして結実する——。そんな**「身体性と情動を伴う新しい没入型生成AI体験（Immersive Generative AI Experience）」**を届けたいという想いから、本プロジェクト「StoryWeaver Live」は誕生しました。

---

## 🚀 主な特徴 (Key Features)

- **🔒 100% 完全ローカル動作（外部API非依存）**:
  ネットワークが不安定なイベント会場やプライバシーが求められる展示現場でも、クラウドAPIを一切介さずローカルPC単体（Windows / GPU: 16GB VRAM）で完全完結。
- **🎙️ 声の演技を聴き分けるハイブリッド音声感情分析**:
  単なる「台本テキストの単語の意味」ではなく、発声の勢い・ピッチ変化・息漏れ・声のトーンを複合的に分析。
- **⚡ VRAM 16GB 制約下でのマルチAIモデル協調稼働**:
  画像生成（ComfyUI / SDXL）、VLM外見抽出（Ollama）、音声感情解析（Qwen2-Audio + Gemma 4）を、動的なモデルのロード・解放（VRAMハンドオフ）により単一の 16GB GPU 上でゼロOOM稼働。
- **🎨 直感的な 5 ステップ・ウィザード UI**:
  シーン選択 ➔ カメラ撮影 ➔ 平常声の測定＆セリフ録音 ➔ 召喚アニメーション演出 ➔ 完成アートカードの提示・朗読。

## 🧠 音声感情分析：Qwen2-Audio × Gemma 4 ハイブリッド解析

本リポジトリには、これまでの開発段階で試行錯誤を重ねてきた**過去の施策（実験・プロトタイプ）**のコードや設定もアーカイブとして含まれています。  
初期は軽量な音声認識モデル（SenseVoiceSmall）単体や、15次元の音響物理特徴量ベクトルによるプロトタイプ辞書マッチング（ユークリッド距離・コサイン類似度）を試作しましたが、最終的に**「人間の耳が感じる微細な演技ニュアンス（囁き・吐息・気迫・照れ）」**を拾い上げるため、2つのオープンモデルをローカルで連携させたハイブリッド解析方式（`qwen2_audio_hybrid.py`）を実装しました。

### 2-Step ハイブリッド解析の仕組み

```text
[ 体験者の発声音声波形 (16kHz) ] ──┬──> [ Step 1: Qwen2-Audio-7B-Instruct (4bit) ]
                                    │      └─ 聴覚的知覚 (感情トーン・叫び・囁きの英語記述)
                                    │
                                    └──> [ 中間層: 音響特徴量 & 個人基準差分 (Semantic Bridge) ]
                                           └─ 声量(ΔRMS), ピッチ(ΔF0), 息漏れ倍率, 澄み具合の言語化
                                                    │
                                                    ▼
                                         [ Step 2: Gemma 4 e2b (Ollama JSON Schema) ]
                                           └─ 聴覚知覚 × 物理変化を統合し、8感情を厳格スコアリング
                                                    │
                                                    ▼
                                         【 基本6感情 ＋ 声質ニュアンス修飾2種 】
```

1. **Step 1: 聴覚的知覚（Qwen2-Audio-7B-Instruct 4bit）**  
   音声を直接聴き取り、話者がどのようなトーン（怒り、喜び、悲しみ、囁き、叫び等）で発声しているかを自然言語（英語）で知覚・抽出します。RTX 3080 Laptop で ComfyUI と共存させるため、bitsandbytes NF4 量子化により VRAM 約 5GB 台で運用しています。
2. **中間層: 音響特徴量のセマンティック変換（Semantic Bridge）**  
   `librosa` を用いて抽出した物理特徴量（音量 RMS, ピッチ F0, スペクトル重心, 息漏れ率）を、体験者の平常時（棒読み）ベースラインと比較し、「声量が大きく増幅」「ピッチが跳ね上がっている」「息成分が普段の2倍多い」といった客観的変化を英語ラベルへ変換します。
3. **Step 2: 論理統合とスコアリング（Gemma 4 e2b via Ollama）**  
   Qwen2-Audio が感じ取った「聴覚知覚」と、音響分析が算出した「客観的物理変化」を Gemma 4 に入力。台本の文字面ではなく、声のトーンと変化量のみを根拠に、JSON Schema 制約を用いて 8 種類の感情（基本6種：喜び、熱狂・気迫、悲哀、驚愕・動揺、自信、平穏 ＋ 声質修飾2種：色気・吐息、照れ）を 0〜5 の整数でメリハリをつけて採点します。
4. **動的 VRAM ハンドオフ**:  
   音声推論が完了すると直ちに Qwen2-Audio および Gemma 4 の VRAM を解放し、後続の ComfyUI（SDXL 画像生成エンジン）へ最大 11GB 超の GPU メモリを即時明け渡すことで、VRAM 16GB の枠組みを厳守しています。

## ⚠️ 現在の課題と今後の改善点 (Known Issues & Limitations)

本システムは現在もアクティブに改良を続けており、特に以下の 2 点において今後の改善・アップデートを予定しています。

### 1. Qwen2-Audio への指示文（プロンプト）の改善
- **現状**: Step 1 における Qwen2-Audio へのプロンプトは現在シンプルな問いかけを採用しています。
- **課題**: 英語の記述ニュアンスに揺らぎが生じる場合があり、声優のような誇張された演技や、日本語特有の繊細なニュアンス（息混じりの語尾、ツンデレ的な照れ、皮肉混じりの笑いなど）を取りこぼすことがあります。
- **今後の展望**: Few-shot 例の提示や、演技スタイル・トーン表現に特化した構造化プロンプト（より豊かな表現を引き出す指示文）へのチューニングを進める予定です。

### 2. 音響物理特徴量のキャリブレーションデータの不足
- **現状**: ピッチ（F0）の変化量、声量差分（ΔRMS）、息漏れ倍率（Spectral Flux / HNR）などの閾値や正規化パラメータは、開発環境における少人数のテスト発声データに基づいて設計されています。
- **課題**: 声の高さや太さ、発声の癖（極端な高音・低音、ハスキーボイス、マイクとの距離・環境ノイズ）など、老若男女の多様な声質に対して常に安定した判定を行うには、サンプリングデータの母数がまだ不足しています。
- **今後の展望**: 多様な話者（年齢・性別・発声スタイル）による音声コーパスでのベンチマーク検証を重ね、動的な適応型スケーリングや閾値の自動最適化を実装していく必要があります。

## 🛠️ システム構成と技術スタック

| コンポーネント | ポート / プロセス | 主要技術 / モデル | 役割 |
| :--- | :--- | :--- | :--- |
| **フロントエンド UI** | `http://localhost:8000` | Vanilla HTML5, CSS3, ES6 JavaScript | カメラ撮影、録音、ウィザード制御、Web Speech API 朗読 |
| **オーケストレーター** | `http://localhost:8000` | FastAPI, Uvicorn, Python Multipart | パイプライン統括、セッション管理、API 集約 |
| **顔特徴抽出 (VLM)** | `http://localhost:11434` | Ollama (`gemma4:e2b`) | 来場者写真からの性別・髪型・髪色・眼鏡等の抽出 |
| **音声感情分析 (Hybrid)** | In-process & Ollama | `Qwen2-Audio-7B-Instruct` (4bit) + `gemma4:e2b` + `librosa` | 棒読み比較による物理変化計測 ＆ 8感情スコアリング |
| **音声認識 (ASR)** | In-process | `FunAudioLLM/SenseVoiceSmall` | 日本語テキスト化（台本セリフとの照合） |
| **画像生成エンジン** | `http://localhost:8188` | ComfyUI (`Animagine XL 3.1 FP8` + `IP-Adapter Plus Face`) | アニメ調SDXLによる高速キャラクターイラスト生成 |

## 💻 動作環境 (System Requirements)

- **OS**: Windows 11 / 10 (WSL2 または PowerShell)
- **GPU**: NVIDIA GeForce RTX 3080 Laptop (VRAM 16GB) 以上推奨
- **RAM**: 32 GB 以上推奨
- **主要ランタイム**:
  - Python 3.10+
  - PyTorch (CUDA 12.x 対応)
  - Ollama (`ollama serve`)
  - ComfyUI (ローカル環境または Pinokio 経由)

## 🏁 クイックスタート (Getting Started)

### 1. リポジトリのクローン
```bash
git clone https://github.com/nasabanaru-sketch/StoryWeaver.git
cd StoryWeaver
```

### 2. 環境設定
`.env.example` を参考に、ローカルのパスや接続ポートを設定してください。
```bash
copy .env.example .env
```

### 3. 各サービスの立ち上げ
1. **ComfyUI**: `http://127.0.0.1:8188` で起動
2. **Ollama**: `ollama serve` を起動し、`gemma4:e2b` を pull
3. **サーバー起動**:
   ```powershell
   # Windows ランチャーを使用する場合
   .\start_storyweaver.bat
   
   # または手動コマンド実行
   python -m uvicorn server:app --host 0.0.0.0 --port 8000
   ```
4. ブラウザで `http://127.0.0.1:8000/` を開いて体験を開始します。
