# データベース・データ永続化規約 (database-rules.md)

本ドキュメントは、StoryWeaver におけるデータ永続化層（セッション履歴、生成結果ログ、プリセット管理等）の設計・運用規約を定めたものです。コード作成・スキーマ変更時に自動適用されます。

---

## 1. データベース選定と動作モード

- **エンジン**: 原則としてローカル軽量 RDBMS（**SQLite**）を使用する。
- **ジャーナルモード**: WAL（Write-Ahead Logging）モードを有効化すること。
  - 同時読み書き時のロック競合を防止する。
  ```sql
  PRAGMA journal_mode = WAL;
  PRAGMA synchronous = NORMAL;
  PRAGMA busy_timeout = 5000;
  ```
- **ORM / クライアント**: SQLAlchemy または aiosqlite を用い、同期/非同期のブロッキングに配慮すること。

---

## 2. スキーマ設計とデータ整合性

### 2.1 主キーとタイムスタンプ
- 全テーブルにおいて以下のカラムを標準装備すること。
  - `id`: 文字列（UUID v4 または ULID）または 自動インクリメント整数
  - `created_at`: UTC ISO-8601 文字列または UNIX タイムスタンプ
  - `updated_at`: 更新日時

### 2.2 外部キー制約
- SQLite においては `PRAGMA foreign_keys = ON;` を接続確立時に明示的に発行すること。

---

## 3. マイグレーション管理

- **ツール**: Alembic または 管理用 Python スクリプト。
- **ルール**:
  - スキーマの直接編集（ALTER TABLE の ad-hoc 実行）を禁止する。
  - マイグレーション適用時は必ず `.agents/workflows/run-migration.md` の定型手順に則ること。
  - すべてのマイグレーションはロールバック（ダウングレード）可能に設計すること。

---

## 4. プライバシー保護とデータライフサイクル規約

### 4.1 体験者生体データ（顔写真・生音声）の保持
- 展示会・イベント利用時、体験者の顔画像（実写）および録音音声は **機微情報（個人情報）** に該当する。
- **実写元データ**: セッション終了後、または展示日終了時に安全に消去（または暗号化/別ストレージ退避）するライフサイクルポリシーを実装すること。
- **生成後アニメ画像**: 記念カード出力用に一定期間保持する場合も、事前の同意ポリシーに準拠すること。

### 4.2 ディスク容量管理
- 生成画像（Base64 / PNG）の蓄積によるディスク枯渇を防止するため、ローテーション処理（例: 最新 500 件保持、古いログの自動アーカイブ）を設けること。
